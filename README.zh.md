# dsh-plugin-live-meeting

DeepSeek Harness 的**会议助手**：在本机实时听取任何通过默认播放设备发声的会议，用本地 SenseVoice 离线转写，再由 DSH 当前配置的模型按**会议领域与主题**校正措辞、按需翻译，滚动生成会议纪要，并允许你针对会议内容提问——问题会优先参考纪要，需要时通过 DSH 的联网搜索补充资料。

> 音频不离开这台电脑。只有转写后的文字会进入你在 DSH 里配置的模型；联网搜索只在提问时按需启用。

---

## 功能

- **系统音频采集**：原生 WASAPI loopback，采集默认播放设备（扬声器/耳机）的声音，不需要虚拟声卡、不需要共享窗口，也不会弹出选择器。
- **本地实时转写**：使用 DSH 官方「语音输入」组合包提供的 SenseVoice 本地识别器；首次使用下载约 240 MB 的 int8 模型，之后离线运行。
- **领域感知校正**：每段话结束后，先显示 ASR 原始文本，再由 LLM 修正同音字、错别字、断句、标点和专有名词。校正提示里会带入你选择的领域（医学、科技、游戏、金融、法律、教育、制造、市场、科研或自定义）和会议主题，让模型选择合适措辞。
- **会议日程参考**：上传、拖拽或直接粘贴 `txt / md / csv / json`，也支持 `PDF / Word / PPT / Excel / ODF` 和 `png / jpg / webp / bmp` 图片。Word/PPT/ODF 直接提取文字；PDF、旧版 Office 和图片由本机 LibreOffice + Windows OCR 处理，文件不离开电脑。上传后不会立即解析：点「应用日程」时才交给当前 DSH 模型识别（乱排版、合并行、OCR 噪声也能拆成时间/姓名/单位/主题四列），并自动识别会议主题与会议领域。面板显示「当前日程」，点一下可在日程列表里手动指定当前环节（会议提前/延后时用）；所有校正、纪要、问答提示都会带上当前时间和日程中的姓名/单位。
- **我的姓名（永久保存）**：在设置里填写「我的姓名 / 我的单位」，保存在本机 `~/.dsh/meetings/profile.json`，重启 DSH、换一场会议都不会丢。它用来判断日程里哪些环节属于你。
- **我的讲词**：上传日程后，**只有日程里出现你的名字时**，插件才会为你生成「我的讲词」（你负责环节的开场、要点、收尾）；只写你的部分，不替别人拟稿。稿件是 Markdown，可读可复制；「生成提示词」里的写作要求可以自己修改。
- **我的角色（永久保存）**：在设置里选「主持人 / 讲者 / 讨论嘉宾 / 参会者」，保存在本机 profile 里。角色决定你要说什么：主持人是开场致辞 + 每个环节的串词 + 结束致辞；讲者和讨论嘉宾只需要感谢主持人的介绍。
- **按点的串词卡片**：串词不会一次性全部生成。听会过程中，插件会在你需要发言的环节**开始前 2 分钟**，结合日程和**已经识别到的内容**生成这一刻要说的话：主持人版先总结上一环节真实讲过的内容，再介绍下一环节的主题和讲者；讲者/嘉宾版就是感谢介绍。卡片出现在「讲词串词」页，也可以点自己的日程环节**立即生成**（会议提前时用）。
- **按音色区分发言人**：本地 CAM++ 声纹嵌入（约 27 MB）把每段话聚类为「发言人 1/2/3」，不依赖云端；同一发言人连续说话会保持同一个标签并按一个发言块展示。日程当前时段的讲者会作为新发言人的建议名称（标记「日程推测」），你可以随时改成真实姓名和单位。
- **同一个发言人不分段**：ASR 仍按约 10 秒切句，但同一发言人的连续句会合并成一个发言块；每分钟再用整段会话做一次二次校正，合并被窗口切开的句子、统一术语和人名。默认只校正、不翻译。
- **逐行翻译（可选）**：默认「不翻译」；需要时可选 English、简体中文、日本語、한국어。校正和翻译在同一次模型调用里完成。
- **麦克风 /「自己」**：可选择采集本机麦克风，你的发言固定标为「自己」，与会议里的发言人区分。建议戴耳机，否则麦克风会再次录到会议声音而出现重复。
- **右侧侧边栏**：打开会议助手时，DSH 主界面向左让出空间，面板成为右侧侧边栏，不再遮挡对话；会话标题栏的「会议助手」图标在听会时变成绿色呼吸闪烁。
- **保留原始识别**：每行可展开「识别原文」，校正失败时回退显示原文并支持一键重试。
- **会议纪要**：不会自动滚动生成；点「生成纪要」时才按当前转写与会议日程写「一句话结论 / 关键讨论 / 决策与结论 / 待办事项 / 风险与未决问题」，会议结束时生成最终版。
- **会议内提问**：回答优先引用会议纪要与转写（带 `[mm:ss]` 时间点），需要时调用 DSH 的 `ctx.web` 联网搜索并列出外部来源。
- **历史会议**：会议转写、纪要和问答保存在 `~/.dsh/meetings/<会议编号>/`，可在面板里回看。
- **主题化界面**：跟随 DSH 明暗主题；入口在会话标题栏右上角，面板可随时关闭。

## 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| DSH | 0.2.1 及以上的 Desktop/Web profile |
| 本地语音 | 在 DSH 插件管理中启用官方 **「语音输入」** 组合包（`@deepseek-ai/dsh-experimental-voice-input-bundle`） |
| 模型 | 本地 SenseVoice int8（约 240 MB）与 CAM++ 声纹嵌入（约 27 MB，按需下载） |
| 模型账号 | DSH 已配置默认模型与凭据（如 DeepSeek Account） |
| 联网搜索 | 可选；DSH 已配置 web 搜索提供方 |

> 为什么需要「语音输入」组合包：它提供 `ctx.speechToText` 服务和 SenseVoice 本地识别器。本插件不重复打包识别模型，也不上传音频到云端。

## 安装

### 方式一：从本地目录安装（开发）

```powershell
# 在 DSH 仓库/桌面版中，把插件链接进 desktop profile
dsh plugin --profile desktop add D:\path\to\dsh-plugin-live-meeting
```

然后在 DSH 的「插件管理」里启用：

1. **官方「语音输入」组合包**（首次必需）；
2. **会议助手**（`dsh-plugin-live-meeting`）。

如果使用手动链接，也可以把包目录放到 profile 的 `node_modules` 下，并在 profile 的 `cordis.patch.yml` 追加：

```yaml
- insert:
    - id: meeting
      name: dsh-plugin-live-meeting
```

### 方式二：从 npm 安装（发布后）

```text
dsh plugin --profile desktop add dsh-plugin-live-meeting

# 或通过 plugin_manager 工具
plugin_manager action=install_bundle target=dsh-plugin-live-meeting@0.2.0
```

安装后按提示启用「语音输入」组合包。

## 首次使用（当天第一次打开会进入初始化）

当天还没有任何会议记录时，打开「会议助手」会直接进入三步初始化，确认完就能开始听会：

1. **我是谁**：填写姓名、单位，并确认角色（主持人 / 讲者 / 讨论嘉宾 / 参会者）。角色会永久保存；日程导入后 AI 还会按日程重新判断一次，你也可以改。
2. **导入会议日程**：上传、拖拽或粘贴日程。支持 `txt / md / csv / json`，`PDF / Word / PPT / Excel / ODF` 和 `png / jpg / webp / bmp` 截图——**PPT 也可以**（幻灯片会被渲染成页面截图，连同提取到的文字一起交给模型；由模型自己判断用文字、看图还是两者结合）。上传后立即由模型解析成结构化日程（同时判断会议主题、会议领域和我的角色），解析结果直接出现在下面的表格里；「应用日程（AI 解析）」用于修改文字后重新解析。
3. **确认会议信息**：确认或修改会议主题、会议领域，并在**结构化日程表格**里直接改时间、讲者、单位、主题，也可以增删行；勾选是否采集我的麦克风（默认开启）。点「完成初始化」即可开始听会。

确认之后，如果**你是主持人**，或者**日程第一项就是你**，插件会立刻为你生成第一张串词（开场致辞 / 上场感谢），不必等到开会。

设置面板里同样是这张结构化表格，随时可改并保存；「重新初始化会议」可以重新走一遍上面的流程。当天已有会议记录时不会自动弹初始化。

## 使用要点

1. **准备本地语音模型**
   - 打开会话右上角的「会议助手」；
   - 点右上角 ⚙ → 在「本地语音模型」卡片点「下载并准备模型」；
   - 约 240 MB，进度会实时显示。下载完成后状态变为「语音模型已就绪」。
   - 开启「按音色区分发言人」时，首次开始会议还会下载约 27 MB 的 CAM++ 声纹模型；不需要区分发言人时可以关闭。
2. **填写我的姓名**
   - 打开设置 →「我的信息」，填写「我的姓名」（可填单位），点「保存我的信息」。
   - 姓名永久保存在本机 `~/.dsh/meetings/profile.json`，重启 DSH 不会丢；清空姓名后保存即可删除。
   - 它是生成讲词的前提：日程里的讲者写法和你的姓名一致时（大小写/空格不敏感，支持包含关系），插件才会认为那个环节属于你。
3. **上传会议日程**（可选，推荐）
   - 设置里的「会议日程」支持上传、拖拽或直接粘贴 `txt / md / csv / json`，也支持 `PDF / Word / PPT / Excel / ODF` 和 `png / jpg / webp / bmp` 图片；Office/PDF 由 DSH 自带的 LibreOffice 在本机渲染，图片用 Windows 本机 OCR，文件不上传；
   - 文本格式示例：
     ```
     14:00-14:30 张医生（市医院） 创面修复病例分享
     14:30-15:00 李主任（省医院）：糖尿病足多学科协作
     15:00-15:20 讨论
     ```
   - CSV：`start,end,speaker,org,topic`；JSON：`[{"start":"14:00","end":"14:30","speaker":"张医生","org":"市医院","topic":"病例分享"}]`。
   - 面板会显示当前日程；校正、纪要和问答会参考当前时间、讲者姓名和单位。
   - 如果日程里出现了你的名字，「讲词串词」页会自动生成属于你的讲词和串词；没有你的名字时不会生成。
4. **设置会议上下文**（开始前或会议中都可以改）
   - **会议主题**：例如「2026 Q3 产品路线图评审」。它会影响校正、翻译、纪要以及讲词的措辞。
   - **会议领域**：医学 / 科技 / 游戏 / 金融 / 法律 / 教育 / 制造 / 市场 / 科研 / 自定义。自定义领域可填「半导体设备」之类的具体方向。
   - **术语表**（可选）：每行 `原文=期望写法`，例如：
     ```
     DSH=DeepSeek Harness
     SenseVoice=本地语音识别
     ```
   - **翻译目标**、**识别语言**、**纪要语言**、**采集设备**。
5. **开始听会**
   - 点「开始听会」；
   - 确认会议软件的扬声器/耳机输出到「系统默认播放设备」（或在设置里选具体设备）；
   - 需要把自己的发言也记下来时，勾选「采集我的麦克风」，你的话会标为「自己」；建议戴耳机，避免麦克风重复收录会议声音。
   - 会采集电脑上所有播放声音，请暂停音乐、视频等其他音频。
6. **看转写、读纪要、提问、看讲词**
   - 「实时转写」：同一个人的连续发言合并为一个发言块；每分钟自动按整段会话做一次二次校正，合并被 10 秒切开的句子。
   - 「会议纪要」：攒够几句话后自动生成，之后滚动更新；结束会议时生成最终版。
   - 「讲词串词」：显示为你生成的参考稿；可以点「重新生成」刷新，或在「生成提示词」里改写作要求（风格、长度、重点）后点「用这个提示词重新生成」；留空则使用默认提示词，「恢复默认提示词」可清空自定义要求。
   - 「提问」：例如「刚才提到的三个风险是什么？」「把预算数字整理一下」「帮我查一下这个政策的最新版本」。联网开关决定是否检索外部资料。

## 它如何工作

```text
会议软件 / 系统声音        我的麦克风（可选）
        │                        │
        ▼                        ▼
Windows WASAPI loopback      WASAPI 麦克风采集
        │  原始 PCM              │  原始 PCM
        └──────────┬─────────────┘
                   ▼
Host：降混 + 重采样到 16 kHz mono，分别做 VAD
                   │
         ┌─────────┴──────────┐
         ▼                    ▼
系统音频：CAM++ 声纹聚类     麦克风：固定标为「自己」
         │                    │
         └─────────┬──────────┘
                   ▼
SenseVoice 本地识别（sherpa-onnx，CPU，离线）
                   │  ASR 原文
                   ▼
DSH 模型（ctx.llm）：领域校正（默认不翻译）
                   │  同一发言人连续句合并成发言块
                   ▼
每分钟：整段会话二次校正（合并被 10 秒窗口切开的句子）
                   │
                   ├── 滚动纪要（ctx.llm，约每 45–90 秒）
                   └── 提问（纪要 + 转写 + 日程 + 可选 ctx.web 搜索）
```

- **音频路径**：浏览器不调用 `getDisplayMedia`/`getUserMedia`（DSH 的 Electron 会话拒绝了所有渲染进程权限），而是由 Host 启动 `native/LoopbackCapture.exe`，通过回环 TCP 把 PCM 交给 Node。exe 随包提供，也可用 `node scripts/build-native.mjs` 从 `native/LoopbackCapture.cs` 重新编译。麦克风使用同一 exe 的 `--source mic` 模式。
- **发言人路径**：每段 VAD 音频在送 ASR 前先过 CAM++ 声纹嵌入，得到 192 维向量；在线余弦聚类把相近向量归到同一个发言人。切换时有连续性保护：与上一位仍较接近的短句不会新建发言人，避免同一人一句话被拆成两个标签。连续同一发言人在界面上合并成一个发言块。
- **麦克风路径**：麦克风音频不参与声纹聚类，固定标为「自己」；与系统音频同时进入同一个 ASR 队列。
- **日程路径**：解析后的日程条目用于当前时段匹配；新建发言人时，如果当前日程只有一位尚未分配的讲者，就把「姓名（单位）」作为建议标签，并在界面上标记「日程推测」。所有姓名/单位都可改。Word/PPT/ODF 直接读 OOXML/ODF 文本；PDF、旧版 Office 和图片由 DSH 自带的 LibreOffice 渲染成本机 PNG 页面后走 Windows OCR；临时文件在识别后删除。
- **讲词/串词路径**：日程条目 + 本机 profile 里的「我的姓名」→ 讲者与姓名匹配的条目被标记为「我的环节」→ 一次 `ctx.llm` 调用，按可编辑的「写作要求」只生成属于我的讲词与串词 → Markdown 保存为 `scripts.md`（进行中的会议）或 `script-draft.json`（还没开始听会时）。没有姓名、或姓名不在日程里时，不调用模型、不生成；只写我的部分，不替别人拟稿。
- **校正策略**：只校正，不改写/不总结/不扩写；数字、日期、金额、姓名保留原样；无法确定的词保留原文。校正失败的句子显示原文并标红，可一键重试。模型没有遵守批量标记格式时，会自动退化为逐句纯文本校正/翻译，保证实时会议不被格式问题卡住。
- **上下文预算**：问答与纪要对转写做尾部截断（约 32–36k 字符），并按发言人合并连续段落，避免长会议把模型上下文撑爆。
- **数据位置**：`~/.dsh/meetings/<id>/meta.json`、`transcript.json`、`summary.md`、`answers.json`、`scripts.md`；我的姓名在 `~/.dsh/meetings/profile.json`，未开始听会时的讲词草稿在 `~/.dsh/meetings/script-draft.json`。原生采集器编译/副本在 `~/.dsh/meetings/.native/`，声纹模型在 `~/.dsh/meetings/.models/`。

## 隐私

- 音频只在本机进程之间通过 `127.0.0.1` 传输，不写入磁盘，不上传。麦克风与系统音频走同一条本机回环通道。
- 日程文件只在 Host 临时目录停留一次转换/OCR 调用，随后立即删除；识别出的文字保存在本机会议目录。Office/PDF 由 DSH 自带的 LibreOffice 在本机渲染，不联网。
- 本地 SenseVoice 推理在 Host 的 CPU 上完成；模型缓存由 DSH 语音输入组合包管理。CAM++ 声纹模型也只在本机 CPU 上运行，用于聚类「是否同一个人」，不用于身份认证。
- 上传的会议日程和发言人名称只保存在本机会议目录；日程会作为提示词的一部分发给模型，与转写文字相同的隐私边界。
- 我的姓名/单位只保存在本机 `~/.dsh/meetings/profile.json`；讲词/串词草稿只保存在本机（`scripts.md` / `script-draft.json`）。只有真正生成讲词时，日程、姓名/单位和写作要求才会进入模型提示词；没有匹配到姓名时不会发送。
- 转写文字会发送给你在 DSH 中配置的模型（用于校正、翻译、纪要与问答）；这与你在 DSH 里正常对话使用同一个提供方和凭据。
- 只有当提问时打开「联网查资料」，问题才会进入 DSH 的 web 搜索提供方；回答中的外部来源会列在气泡下方。
- 会议记录保存在本机 `~/.dsh/meetings`，不会自动同步。

## 已知限制

- **仅 Windows x64**：采集器使用 WASAPI；其他平台会明确报错。
- **麦克风回声**：同时采集系统声音和麦克风时，如果外放而不是戴耳机，麦克风会再次录到会议声音，出现「自己」与发言人重复。建议戴耳机，或在设置里关闭麦克风。
- **二次校正有长度上限**：每分钟的整段校正在约 14k 字符的最近会话范围内进行；更早的发言仍保留原校正结果，不会被丢弃。
- **日程文件 OCR/提取**：Word/PPT/ODF 直接提取文字，准确度高；PDF、旧版 `.doc/.ppt/.xls` 和图片走 LibreOffice 渲染 + Windows OCR，复杂排版/低分辨率可能识别不准。识别失败时仍可手动粘贴文字日程。
- **没有说话人实名识别**：音色聚类只能回答「这几段是不是同一个人」，不能知道姓名。日程只提供建议名称；真实姓名需要你手动填写，或以后做声纹注册（需要本人同意）。
- **发言人可能被合并或拆开**：音色相近、短促应答、重叠说话、变声/远场麦克风都可能影响聚类。面板提供灵敏度调节和手动改名；同一发言人连续说话已做连续性保护，但无法保证 100%。
- **日程建议可能不准**：当前日程只有一位讲者时会自动建议该姓名（标记「日程推测」）；如果实际说话人不是日程上的那位，请直接改名。
- **日程时间按本机时钟匹配**：日程使用本地时区的 `HH:MM`；跨时区或延迟开始时，「当前日程」可能偏早/偏晚，可手动改日程。
- **讲词/串词是参考稿**：模型按日程和你的姓名生成，可能写得空泛，或与你的真实意图有出入；不会替别人拟稿。建议会前过一遍，或在「生成提示词」里补充你的风格、重点和长度要求后重新生成。
- **姓名匹配是字面匹配**：只有日程讲者与「我的姓名」相同或互相包含时才算「我的环节」（忽略空格和间隔号）。日程里写「张主任」而姓名是「张伟」时匹配不到，需要把日程改成一致写法，或把姓名改成日程里的写法；修改后点「重新生成」。
- **修改日程后讲词可能过期**：日程更新时，如果姓名仍匹配会自动重写，否则只在页面上提示过期；改主题或写作要求不会自动重写，需要点「重新生成」。
- **采集的是整个默认播放设备**，不是单个应用。会混入系统提示音、音乐等；请会议期间保持安静。
- **没有说话人分离**（重叠语音）：转写按停顿切句；两个人同时说话时无法把两路声音拆开。
- **SenseVoice 是非流式识别**：一句话说完、停顿约 0.6 秒后才出整句；不是逐字上屏。
- **长句会被 20 秒切断**：连续不停顿的长篇发言会按 20 秒分段。
- **领域校正依赖模型质量**：专有名词最好写进术语表；模型仍可能改错，原文始终保留。
- **模型下载**：SenseVoice 首次约 240 MB，CAM++ 约 27 MB；HuggingFace/GitHub 不可达时会尝试镜像。下载失败会在面板里显示原因。
- **DSH 升级**：`@deepseek-ai/dsh-experimental-*` 是实验性包，升级后 API 可能变化；本插件只依赖 `ctx.speechToText`、`ctx.llm`、`ctx.web` 与 `webServer` 的稳定面。

## 故障排查

| 现象 | 处理 |
|---|---|
| 面板显示「语音服务未启用」 | 在 DSH 插件管理中启用官方「语音输入」组合包，然后刷新页面。 |
| 模型一直 `unprepared` | 打开设置点「下载并准备模型」；若下载失败，检查网络/代理，或配置 `modelOrigins` 使用可达镜像。 |
| 开始后没有转写 | 确认会议声音从默认播放设备输出；在设置里换采集设备；确认系统音量非静音；查看面板底部语音状态。 |
| 转写有内容但没有校正/翻译 | 检查 DSH 默认模型与账号；面板底部会显示当前 provider/model。 |
| 提问没有联网结果 | DSH 未配置 web 搜索提供方，或搜索失败；回答仍会基于会议内容。 |
| 发言人被拆开/合并 | 调低/调高「发言人区分灵敏度」（0.58 更敏感、0.74 更容易合并），或直接改名；短促应答和重叠说话最容易出错。 |
| 日程的「当前」不对 | 点顶部日程条，在下拉列表里手动指定当前环节；恢复自动判断选「按时间自动判断」。 |
| 讲词/串词没有生成 | 确认「我的信息」里的姓名已保存、且日程里的讲者写法和它一致（空格不敏感，支持包含关系）；只有姓名出现在日程里才会生成。也可以点「讲词串词」页的「重新生成」查看具体原因。 |
| 讲词生成失败/一直报模型错误 | 检查 DSH 默认模型与账号；「讲词串词」页会显示模型返回的错误。修改「生成提示词」后重试，或清空提示词用默认要求。 |
| 改了提示词但内容没变 | 修改提示词只是编辑文本，需要再点「用这个提示词重新生成」才会生效。 |
| 日程图片/文件识别不出来 | 换更清晰、正对屏幕的截图，或改用 Word/PPT/文字版 PDF；Windows OCR 需要中文语言包（本机已检测到 `zh-Hans-CN`）。也可以直接把文字粘贴到日程框。 |
| 麦克风没有「自己」 | 检查 Windows 麦克风隐私设置允许桌面应用使用麦克风；在设置里选对麦克风设备；开始听会后再说话。 |
| 「自己」和发言人的话重复 | 外放导致麦克风再次录到会议声音；戴耳机，或关闭「采集我的麦克风」。 |
| 侧边栏没有让出空间/图标不绿 | 刷新页面加载最新 `client.js`；图标只在 `listening`/`capturing` 时绿色呼吸，`preparing` 是琥珀色，`error` 是红色。 |
| 每分钟二次校正没有更新 | 只有出现新转写且距上次校正约 1 分钟时才会触发；可点「重新生成纪要」旁的刷新或等待下一次。 |
| 声纹模型下载失败 | 关闭「按音色区分发言人」仍可正常转写；或手动把 CAM++ 模型放到 `~/.dsh/meetings/.models/campplus_zh_16k.onnx`。 |
| 面板打不开 | 确认插件已启用并刷新页面；查看 DSH 日志里是否有 `meeting` 相关错误。 |
| 采集器启动失败 | 删除 `~/.dsh/meetings/.native/` 后重试；或运行 `node scripts/build-native.mjs` 重新生成 exe。 |

## 第三方组件

- **SenseVoiceSmall**（FunAudioLLM / ModelScope）：由 DSH 官方「语音输入」组合包按需下载并在本地 CPU 上推理。
- **CAM++ 说话人嵌入**（3D-Speaker / 通义实验室，Apache-2.0）：本插件从 sherpa-onnx 发布页按需下载，只用于本机聚类，不做身份认证。
- **sherpa-onnx / onnxruntime**：随 DSH 安装，本插件通过 DSH 的 `sherpa-onnx-node` 加载，不重复分发原生运行时。
- **Windows OCR**：通过 `native/ocr-agenda.ps1` 调用系统 `Windows.Media.Ocr`，只处理本机日程截图。
- **LibreOffice Kit**：使用 DSH 自带的 `@deepseek-ai/libreoffice-kit` 在本机把 PDF/旧版 Office 渲染为 PNG 页面，再交给 Windows OCR。
- **WASAPI**：同一 `native/LoopbackCapture.exe` 支持 `--source loopback`（系统声音）和 `--source mic`（麦克风）。
- **WASAPI loopback**：通过 Windows 自带的 .NET Framework 编译/运行 `native/LoopbackCapture.cs`，不依赖第三方音频库。

## 刷新与重启

- 第一次安装/启用插件后，刷新正在使用的 DSH 页面（或重启 DSH），让浏览器加载 `client.js`。
- 修改 `client.js` 后刷新页面；修改 Host 侧 `lib/*.mjs` 后，DSH 的 HMR 会重新加载插件（没有 HMR 时重启 DSH）。
- 会议进行中刷新页面不会中断 Host 的采集；重新打开面板会从 `/dsh-meeting/state` 恢复当前会议。
- 「我的姓名」和讲词草稿保存在本机，刷新页面、重启 DSH、换一场会议都不会丢；未开始听会时上传日程生成的讲词会随 `script-draft.json` 恢复，开始听会后写入该会议的 `meta.json` / `scripts.md`。

## 开发

```text
index.js                 Host 入口：路由注册、生命周期
client.js                Web 客户端：标题栏入口 + 右侧侧边栏（portal 到 body）
lib/meeting.mjs          会议状态机：采集、ASR 队列、校正队列、纪要、问答、持久化
lib/routes.mjs           HTTP/SSE 路由
lib/native.mjs           WASAPI 采集器构建/启动、设备枚举
lib/audio.mjs            降混、重采样、VAD、WAV 编码
lib/asr.mjs              ctx.speechToText 适配与模型准备
lib/speaker.mjs          CAM++ 声纹嵌入、在线聚类、模型下载
lib/agenda.mjs           日程解析、当前时段、姓名/单位参考
lib/script.mjs           讲词/串词提示词、「我的环节」姓名匹配
lib/office.mjs           PDF/Word/PPT/Excel/ODF 文本提取与 LibreOffice 渲染
lib/ai.mjs               ctx.llm 校正/翻译/纪要/讲词/问答，ctx.web 搜索
lib/util.mjs             HTTP/文本工具
native/LoopbackCapture.cs  WASAPI loopback / 麦克风采集器（C# / .NET Framework 4.x）
native/ocr-agenda.ps1      Windows 本机 OCR（日程图片）
scripts/build-native.mjs  重新编译 native exe
```

```powershell
cd dsh-plugin-live-meeting
npm run check            # node --check 全部入口
npm run selftest         # 日程解析、讲词提示词、声纹聚类、重采样/VAD 的纯本地测试
node scripts/build-native.mjs --check
```

安装到运行中的 DSH 后，修改 `client.js` 需要刷新页面；Host 侧模块由 DSH 的 HMR 重新加载。
